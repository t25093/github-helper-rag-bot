# README, רישיון וקבצי תיעוד בפרויקט

קובץ זה מסביר אילו קבצי תיעוד כדאי שיהיו בכל פרויקט בגיטהב, ומה לכתוב בהם.

## מה זה README ולמה הוא חשוב

`README.md` הוא הקובץ שמוצג אוטומטית בעמוד הראשי של המאגר, מתחת לרשימת הקבצים. זה הדבר הראשון שכל מבקר רואה, ולכן הוא צריך להסביר בקצרה: מה הפרויקט, איך מתקינים ואיך משתמשים.

פרויקט בלי README נראה לא גמור, וקשה לאחרים (וגם לך בעוד חצי שנה) להבין אותו.

## מה לכתוב ב-README

מבנה מומלץ:
```
# שם הפרויקט

תיאור קצר: מה הפרויקט עושה ולמי הוא מיועד.

## התקנה
הצעדים להתקנה, כולל פקודות.

## שימוש
איך מריצים, עם דוגמה.

## טכנולוגיות
שפות, ספריות וכלים עיקריים.

## רישיון
סוג הרישיון.
```

אפשר להוסיף לפי הצורך: צילומי מסך, הוראות לתרומה לפרויקט, רשימת יוצרים ופרטי קשר.

## יצירת README

**בעת יצירת מאגר חדש:** סמן **Add a README file**. (לא לסמן אם מתכוונים להעלות פרויקט קיים מהמחשב. ראה בתסריט העלאת פרויקט.)

**במאגר קיים, דרך האתר:** **Add file** ← **Create new file**, ושם הקובץ `README.md`.

**דרך המחשב:** יוצרים קובץ `README.md` בתיקייה הראשית, ואז:
```
git add README.md
git commit -m "add README"
git push
```

## יסודות Markdown לכתיבת README

קבצי `.md` נכתבים ב-Markdown, תחביר פשוט שגיטהב מציג בעיצוב:
```
# כותרת ראשית
## כותרת משנה
**טקסט מודגש**
*טקסט נטוי*
- פריט ברשימה
1. פריט ממוספר
[טקסט הקישור](https://example.com)
![תיאור התמונה](images/screenshot.png)
`קוד בתוך שורה`
```
לבלוק קוד, מקיפים את הקוד בשלוש גרשיים הפוכים (```) בשורה לפני ובשורה אחרי.

## למה צריך רישיון

כשאין רישיון בפרויקט, לפי החוק כל הזכויות שמורות ליוצר, גם אם המאגר ציבורי. כלומר, אחרים יכולים לצפות בקוד, אבל אין להם רשות חוקית להעתיק אותו, לשנות אותו או להשתמש בו בפרויקט משלהם. רישיון קובע במפורש מה מותר.

## רישיונות נפוצים

- **MIT:** מתירני מאוד. כל אחד יכול להשתמש, לשנות ולהפיץ, גם מסחרית, בתנאי ששומרים את הודעת זכויות היוצרים. נפוץ מאוד בפרויקטים קטנים.
- **Apache 2.0:** מתירני, דומה ל-MIT, ומוסיף התייחסות מפורשת לפטנטים.
- **GPL v3:** מי שמפיץ גרסה משונה של הקוד חייב לפרסם גם אותה תחת אותו רישיון.

לעזרה בבחירה, האתר choosealicense.com (של GitHub) מסביר את ההבדלים.

## הוספת רישיון למאגר

1. בדף המאגר ← **Add file** ← **Create new file**.
2. בשם הקובץ הקלד `LICENSE`. יופיע כפתור **Choose a license template**.
3. בחר רישיון, מלא את הפרטים ולחץ **Review and submit**.
4. בצע commit.

אפשר גם לבחור רישיון כבר בעת יצירת מאגר חדש.

## קבצי תיעוד נוספים

קבצים שגיטהב מזהה ומציג במקומות מיוחדים:
- **`CONTRIBUTING.md`:** הנחיות למי שרוצה לתרום לפרויקט. מוצג כשפותחים Issue או Pull Request.
- **`CHANGELOG.md`:** רשימת השינויים בכל גרסה.
- **`CODE_OF_CONDUCT.md`:** כללי התנהגות בקהילת הפרויקט.
- **`SECURITY.md`:** איך לדווח על בעיית אבטחה.

לפרויקט קטן מספיקים README ו-LICENSE.

## תיאור ונושאים בעמוד המאגר

בעמוד הראשי של המאגר, בצד ימין באזור **About**, לחץ על סמל גלגל השיניים כדי להוסיף:
- **Description:** משפט אחד שמתאר את הפרויקט
- **Website:** קישור לאתר הפרויקט, אם יש
- **Topics:** תגיות כמו `python`, `rag`, `chatbot`, שעוזרות לאחרים למצוא את הפרויקט
