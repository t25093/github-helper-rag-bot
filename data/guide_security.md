# אבטחה ופרטיות בפרויקטים בגיטהב

קובץ זה מסביר איך שומרים על סיסמאות, מפתחות ומידע רגיש, ומה עושים אם משהו דלף.

## מה אסור להעלות לגיטהב

לעולם אין להעלות למאגר, גם לא למאגר פרטי:
- סיסמאות
- מפתחות API וטוקנים
- קבצי הגדרות עם פרטי התחברות למסדי נתונים
- מפתחות SSH פרטיים
- מידע אישי של אנשים אחרים

**חשוב להבין:** גם אם מוחקים קובץ ב-commit מאוחר יותר, הוא נשאר בהיסטוריה של המאגר, וכל מי שיש לו גישה יכול למצוא אותו.

## שמירת סודות בקובץ .env

הדרך המקובלת היא לשמור סודות בקובץ נפרד בשם `.env`, ולמנוע את העלאתו:

1. צור קובץ `.env` בתיקיית הפרויקט:
   ```
   API_KEY=your-secret-key
   ```
2. הוסף אותו לקובץ `.gitignore`:
   ```
   .env
   ```
3. בקוד, קרא את הערך ממשתני הסביבה ולא כתוב אותו ישירות.
4. צור קובץ `.env.example` עם שמות המשתנים בלבד, בלי ערכים אמיתיים, והעלה אותו. כך אחרים יודעים אילו משתנים צריך להגדיר:
   ```
   API_KEY=
   ```

## בדיקה לפני commit

לפני `git add .`, כדאי להריץ:
```
git status
```
ולוודא שלא מופיעים קבצים רגישים ברשימה. אם `.env` מופיע, הוא חסר ב-`.gitignore`.

## מה לעשות אם סיסמה או מפתח הועלו לגיטהב

1. **מיד לבטל את המפתח או להחליף את הסיסמה** אצל השירות שהנפיק אותם. זה הצעד החשוב ביותר. ברגע שסוד הגיע למאגר, יש להניח שהוא כבר נחשף, גם אם תמחק אותו מהר.
2. להוציא מפתח חדש ולשמור אותו ב-`.env`.
3. להוסיף את הקובץ ל-`.gitignore` ולהסיר אותו מהמעקב:
   ```
   git rm --cached .env
   git commit -m "stop tracking .env"
   git push
   ```
4. אם רוצים להסיר את הסוד גם מההיסטוריה, צריך כלי כמו `git filter-repo`. זו פעולה מתקדמת, והיא לא מחליפה את צעד 1.

## הגנה אוטומטית של GitHub על סודות

GitHub סורק מאגרים ומזהה סוגים נפוצים של מפתחות וטוקנים (Secret scanning). בחלק מהמקרים הוא גם חוסם push שמכיל מפתח מוכר (Push protection), ומציג הודעה שמסבירה מה זוהה. אם קיבלת הודעה כזו, הסר את הסוד מהקוד במקום לעקוף את החסימה.

## אימות דו-שלבי (2FA)

מומלץ מאוד להפעיל אימות דו-שלבי בחשבון GitHub, ו-GitHub מחייב אותו בחשבונות רבים שתורמים קוד.

להפעלה: לחץ על תמונת הפרופיל ← **Settings** ← **Password and authentication** ← **Two-factor authentication** ← **Enable**. אפשר להשתמש באפליקציית אימות או במפתח אבטחה.

**חשוב:** שמור את קודי השחזור (recovery codes) במקום בטוח. בלעדיהם, אם תאבד את הטלפון, ייתכן שלא תוכל להיכנס לחשבון.

## עדכוני אבטחה לספריות (Dependabot)

פרויקטים משתמשים בספריות חיצוניות, ולפעמים מתגלות בהן פרצות. Dependabot של GitHub:
- **Dependabot alerts:** מתריע כשספרייה שבשימוש בפרויקט מכילה פרצה ידועה.
- **Dependabot security updates:** פותח אוטומטית Pull Request שמעדכן את הספרייה לגרסה מתוקנת.

להפעלה: **Settings** ← **Code security** (או **Code security and analysis**) ← הפעל את האפשרויות של Dependabot.

## סודות לבדיקות אוטומטיות (GitHub Actions)

כשבדיקה אוטומטית צריכה מפתח, לא כותבים אותו בקובץ ה-workflow, אלא שומרים אותו כסוד מוצפן:
**Settings** ← **Secrets and variables** ← **Actions** ← **New repository secret**.

בקובץ ה-workflow ניגשים אליו כך:
```
${{ secrets.API_KEY }}
```
ראה בקובץ GitHub Actions ו-GitHub Pages.
