# GitHub Actions ו-GitHub Pages - אוטומציה ופרסום אתר

קובץ זה מסביר שני כלים שימושיים לתחזוקת פרויקט: הרצת בדיקות אוטומטיות, ופרסום אתר ישירות מהמאגר.

## מה זה GitHub Actions

GitHub Actions מריץ פעולות אוטומטיות כשקורה משהו במאגר, למשל בכל push או בכל פתיחה של Pull Request. שימושים נפוצים:
- הרצת בדיקות (tests) כדי לוודא שהשינוי לא שבר כלום
- בדיקת סגנון קוד
- בנייה ופרסום של הפרויקט

התוצאה מוצגת ליד כל commit ו-Pull Request: סימן ✓ ירוק אם הכל עבר, ו-✗ אדום אם משהו נכשל.

## איך מגדירים workflow

פעולה אוטומטית מוגדרת בקובץ YAML בתיקייה `.github/workflows/` במאגר. כל קובץ כזה נקרא workflow.

**הדרך הפשוטה:** בדף המאגר ← לשונית **Actions**. גיטהב מציע תבניות מוכנות לפי שפת הפרויקט. בחר תבנית ← **Configure** ← בצע commit.

## דוגמה: הרצת בדיקות לפרויקט Python

קובץ `.github/workflows/tests.yml`:
```yaml
name: Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pytest
```

הסבר:
- **`on`:** מתי להריץ. כאן: בכל push ובכל Pull Request.
- **`runs-on`:** על איזו מערכת הפעלה להריץ.
- **`steps`:** הצעדים: הורדת הקוד, התקנת Python, התקנת הספריות והרצת הבדיקות.

מספרי הגרסאות של הפעולות (`@v4`, `@v5`) מתעדכנים מדי פעם. את הגרסה העדכנית אפשר לראות ב-GitHub Marketplace.

## צפייה בתוצאות ותיקון כשל

1. לשונית **Actions** מציגה את כל ההרצות.
2. לחיצה על הרצה ← לחיצה על ה-job ← רואים את הפלט של כל צעד.
3. הצעד שנכשל מסומן באדום, ושם מופיעה הודעת השגיאה.
4. מתקנים את הבעיה בקוד, מבצעים commit ו-push, וההרצה מתבצעת מחדש אוטומטית.

אפשר גם להריץ שוב בלי שינוי: **Re-run jobs**.

## מגבלות שימוש ב-Actions

במאגרים ציבוריים, הרצות על השרתים הרגילים של GitHub הן ללא עלות. במאגרים פרטיים יש מכסת דקות חודשית לפי סוג החשבון. את השימוש הנוכחי רואים בהגדרות החשבון, באזור החיוב (Billing).

## מה זה GitHub Pages

GitHub Pages מפרסם אתר סטטי (HTML, CSS, JavaScript) ישירות מקבצים במאגר, בכתובת כמו:
```
https://USER.github.io/REPO/
```
שימושים נפוצים: אתר לפרויקט, תיק עבודות אישי, אתר תיעוד.

Pages מתאים לאתרים סטטיים בלבד. הוא לא מריץ קוד שרת (כמו Python או מסד נתונים).

## פרסום אתר עם GitHub Pages

1. ודא שבמאגר יש קובץ `index.html` (בתיקייה הראשית או בתיקייה `docs`).
2. **Settings** ← **Pages**.
3. באזור **Build and deployment**, תחת **Source**, בחר **Deploy from a branch**.
4. בחר ענף (בדרך כלל `main`) ותיקייה (`/root` או `/docs`) ← **Save**.
5. אחרי דקה או שתיים, הכתובת של האתר תופיע בראש אותו עמוד.

בחשבון חינמי, Pages זמין למאגרים ציבוריים. כל push לענף שנבחר מעדכן את האתר אוטומטית.

## אתר אישי בכתובת הראשית

אם יוצרים מאגר בשם המיוחד `USER.github.io` (כש-USER הוא שם המשתמש שלך), האתר שלו יפורסם בכתובת הראשית:
```
https://USER.github.io/
```
זה מקום מקובל לתיק עבודות או לאתר אישי.
