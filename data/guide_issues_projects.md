# Issues וניהול משימות בגיטהב

קובץ זה מסביר איך מנהלים תקלות, משימות ורעיונות לפרויקט בעזרת Issues ו-Projects.

## מה זה Issue

Issue הוא כרטיס שמתעד דבר אחד שצריך לטפל בו בפרויקט: תקלה (bug), תכונה חדשה, שאלה או משימה. לכל Issue יש מספר (למשל #12), כותרת, תיאור, ודיון בתגובות.

שימושים נפוצים:
- משתמש מדווח על תקלה
- רשימת משימות לפיתוח
- תיאום בצוות: מי עובד על מה
- איסוף רעיונות לשיפור

## פתיחת Issue

1. בדף המאגר ← לשונית **Issues** ← **New issue**.
2. כתוב כותרת קצרה וברורה, למשל "כפתור השמירה לא עובד בטופס הרשמה".
3. בתיאור כדאי לכלול: מה קרה, מה היה צפוי לקרות, ואיך משחזרים את התקלה.
4. לחץ **Create** (או **Submit new issue**).

אם הלשונית **Issues** לא מופיעה, היא כבויה בהגדרות: **Settings** ← **General** ← אזור **Features** ← סמן **Issues**.

## ארגון Issues: תוויות, אחראים ואבני דרך

- **Labels (תוויות):** סיווג לפי סוג, למשל `bug`, `enhancement`, `documentation`, `good first issue`. אפשר ליצור תוויות משלך.
- **Assignees (אחראים):** מי מטפל ב-Issue. כך יודעים מי עובד על מה.
- **Milestones (אבני דרך):** קיבוץ Issues לפי יעד, למשל "גרסה 1.0" או "הגשה ראשונה". מציג אחוז התקדמות.

את כל אלה מגדירים בצד ימין של דף ה-Issue.

## סגירת Issue

**ידנית:** בתחתית דף ה-Issue ← **Close issue**.

**אוטומטית מ-Pull Request:** כותבים בתיאור ה-PR מילת סגירה ואחריה מספר ה-Issue, למשל:
```
Fixes #12
```
כשה-PR ממוזג לענף הראשי, ה-Issue נסגר אוטומטית. מילים שעובדות: `close`, `closes`, `closed`, `fix`, `fixes`, `fixed`, `resolve`, `resolves`, `resolved`.

## קישור בין Issues, Pull Requests ו-commits

- כתיבת `#12` בכל מקום (בהודעת commit, ב-PR או בתגובה) יוצרת קישור ל-Issue מספר 12.
- כתיבת `@username` מזכירה משתמש ושולחת לו התראה.

כך ההיסטוריה של כל תקלה מתועדת: איפה דווחה, איזה קוד תיקן אותה, ומי טיפל בה.

## תבניות ל-Issues

כדי שדיווחים יגיעו מסודרים, אפשר להגדיר תבניות:
**Settings** ← **General** ← אזור **Features** ← ליד Issues לחץ **Set up templates**.

התבניות נשמרות במאגר בתיקייה `.github/ISSUE_TEMPLATE/`. אפשר ליצור למשל תבנית לדיווח תקלה ותבנית לבקשת תכונה.

## לוח משימות (Projects)

GitHub Projects הוא לוח לניהול משימות, שמציג Issues ו-Pull Requests בתצוגות שונות:
- **Board:** עמודות, למשל "לביצוע", "בעבודה", "הושלם". גוררים כרטיסים בין עמודות.
- **Table:** טבלה עם שדות כמו סטטוס, אחראי ותאריך.
- **Roadmap:** ציר זמן.

**יצירה:** בדף המאגר ← לשונית **Projects** ← **New project**, ובחר תבנית. אחר כך מוסיפים Issues קיימים ללוח.

לפרויקט לימודי של צוות, לוח Board עם שלוש עמודות פשוטות מספיק בהחלט.

## Discussions: מקום לשאלות ודיונים

כשיש שאלות כלליות שאינן תקלה או משימה, אפשר להפעיל את **Discussions**: **Settings** ← **General** ← **Features** ← **Discussions**. זה פורום קטן בתוך המאגר, וכך ה-Issues נשארים רק לדברים שצריך לטפל בהם.
