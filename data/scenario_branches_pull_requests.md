# ענפים ו-Pull Requests - עבודה מסודרת על שינויים

קובץ זה מסביר איך עובדים עם ענפים (branches) ו-Pull Requests: הדרך המקובלת להוסיף שינויים לפרויקט בלי לפגוע בגרסה הראשית.

## מה זה ענף ולמה צריך אותו

ענף הוא קו פיתוח נפרד בתוך המאגר. הענף הראשי (בדרך כלל `main`) מכיל את הגרסה היציבה של הפרויקט. כשרוצים להוסיף תכונה חדשה או לתקן תקלה, פותחים ענף חדש, עובדים בו, ורק כשהעבודה מוכנה ונבדקה, ממזגים אותה לענף הראשי.

היתרונות:
- הגרסה הראשית נשארת תקינה גם כשעבודה חדשה עוד לא גמורה.
- אפשר לעבוד על כמה דברים במקביל, כל אחד בענף משלו.
- בעבודת צוות, כל אחד עובד בענף שלו בלי להפריע לאחרים.

## יצירת ענף חדש ומעבר אליו

```
git switch -c feature-login
```
הפקודה יוצרת ענף חדש בשם `feature-login` ועוברת אליו. (בגרסאות ישנות של Git: `git checkout -b feature-login`.)

מומלץ לתת שמות שמתארים את העבודה, למשל:
- `feature-login` לתכונה חדשה
- `fix-upload-error` לתיקון תקלה
- `docs-readme` לעדכון תיעוד

## הצגת ענפים ומעבר בין ענפים

הצגת הענפים המקומיים (הענף הנוכחי מסומן בכוכבית):
```
git branch
```

הצגת כל הענפים, כולל אלה שבגיטהב:
```
git branch -a
```

מעבר לענף קיים:
```
git switch main
```

**שים לב:** לפני מעבר ענף כדאי לבצע commit לשינויים, או להניח אותם בצד עם `git stash`. אחרת Git עלול לסרב לעבור.

## העלאת ענף לגיטהב

בפעם הראשונה שמעלים ענף חדש:
```
git push -u origin feature-login
```
מהפעם השנייה מספיק `git push`.

## מה זה Pull Request

Pull Request (נקרא גם PR) הוא בקשה למזג שינויים מענף אחד לענף אחר, בדרך כלל מענף עבודה לענף `main`. ה-PR מאפשר:
- לראות בדיוק אילו שינויים נעשו
- לקבל הערות ובדיקה (review) מחברי צוות לפני המיזוג
- להריץ בדיקות אוטומטיות על השינויים
- לשמור תיעוד של מה שונה ולמה

## פתיחת Pull Request

1. העלה את הענף לגיטהב (`git push -u origin feature-login`).
2. היכנס לדף המאגר. בדרך כלל יופיע פס צהוב עם הצעה לפתוח PR לענף שהועלה, לחץ **Compare & pull request**.
   אם הפס לא מופיע: לשונית **Pull requests** ← **New pull request**, ובחר את הענפים.
3. ודא שהכיוון נכון: **base** הוא הענף שאליו ממזגים (בדרך כלל `main`), ו-**compare** הוא הענף שלך.
4. כתוב כותרת ותיאור: מה שינית, למה, ואיך לבדוק.
5. לחץ **Create pull request**.

אם העבודה עוד לא מוכנה אבל רוצים לשתף אותה, אפשר לפתוח **Draft pull request** (טיוטה). אי אפשר למזג טיוטה עד שמסמנים אותה כמוכנה.

## בדיקת Pull Request (Code Review)

מי שבודק את ה-PR:
1. נכנס ללשונית **Files changed** ורואה את כל השינויים.
2. יכול להוסיף הערה על שורה מסוימת בלחיצה על סימן + ליד השורה.
3. בסיום לוחץ **Review changes** ובוחר:
   - **Comment**: הערות כלליות, בלי החלטה
   - **Approve**: אישור השינויים
   - **Request changes**: בקשה לתיקונים לפני מיזוג

כדי לתקן לפי ההערות, פשוט ממשיכים לעבוד באותו ענף, מבצעים commit ו-push, וה-PR מתעדכן אוטומטית.

## מיזוג Pull Request

בדף ה-PR לוחצים על כפתור המיזוג. יש שלוש אפשרויות:
- **Create a merge commit**: שומר את כל ה-commits של הענף, ומוסיף commit של מיזוג. האפשרות הרגילה.
- **Squash and merge**: מאחד את כל ה-commits של הענף ל-commit אחד. נותן היסטוריה נקייה.
- **Rebase and merge**: מוסיף את ה-commits אחד אחד, בלי commit מיזוג.

למתחילים, **Create a merge commit** או **Squash and merge** הן הבחירות הפשוטות.

אחרי המיזוג, GitHub מציע למחוק את הענף (**Delete branch**). מומלץ למחוק, כי העבודה כבר נמצאת ב-`main`.

## עדכון המחשב אחרי מיזוג

אחרי שה-PR מוזג בגיטהב, הענף `main` במחשב שלך עדיין ישן. כדי לעדכן:
```
git switch main
git pull
git branch -d feature-login
```
הפקודה האחרונה מוחקת את הענף המקומי שכבר מוזג.

## קונפליקט ב-Pull Request

אם GitHub מציג הודעה שיש קונפליקט ואי אפשר למזג אוטומטית, אפשר לפתור כך:

**דרך האתר** (לקונפליקטים פשוטים): לחץ **Resolve conflicts**, ערוך את הקבצים והסר את סימני הקונפליקט, ואז **Mark as resolved** ו-**Commit merge**.

**דרך המחשב:**
```
git switch feature-login
git pull origin main
```
פתור את הקונפליקטים בקבצים (ראה בקובץ השגיאות הנפוצות, סעיף CONFLICT), ואז:
```
git add .
git commit -m "resolve conflicts with main"
git push
```

## סיכום תהליך העבודה עם ענפים

```
git switch main
git pull
git switch -c feature-name
(עבודה על הקבצים)
git add .
git commit -m "תיאור השינוי"
git push -u origin feature-name
(פתיחת Pull Request באתר, בדיקה ומיזוג)
git switch main
git pull
git branch -d feature-name
```
