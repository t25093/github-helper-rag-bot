# תסריט העלאת פרויקט לגיטהב

קובץ זה מסביר איך מעלים לגיטהב פרויקט שנמצא במחשב ועוד לא נמצא בגיטהב, ואיך מעלים אליו עדכונים אחר כך. לפני כן צריך ש-Git יהיה מותקן ומוגדר במחשב (שם ואימייל), ושיהיה חשבון בגיטהב.

## שתי הדרכים להעלות פרויקט

| דרך | מתי מתאימה |
|---|---|
| דרך שורת הפקודה (Git) | הדרך המומלצת. שומרת היסטוריה, ומאפשרת להעלות עדכונים בקלות עם `git push` |
| דרך אתר גיטהב (Upload files) | לקבצים בודדים או כשאין Git במחשב. לא מתאימה לעבודה שוטפת |

## שלב 1: יצירת מאגר ריק בגיטהב

1. נכנסים ל-github.com ומתחברים.
2. למעלה מימין לוחצים על **+** ← **New repository**.
3. ב-**Repository name** כותבים שם לפרויקט, למשל `my-project`.
4. בוחרים **Public** (כולם יכולים לראות) או **Private** (רק את/ה ומי שהזמנת).
5. **לא מסמנים** Add a README file, לא בוחרים .gitignore ולא בוחרים License. כשמעלים פרויקט קיים מהמחשב, המאגר בגיטהב צריך להיות ריק, אחרת ה-push הראשון ייכשל.
6. לוחצים **Create repository**.
7. מעתיקים את כתובת המאגר שמופיעה בעמוד, בצורה `https://github.com/USER/my-project.git`.

## שלב 2: פתיחת טרמינל בתיקיית הפרויקט

- **Windows:** פותחים את תיקיית הפרויקט בסייר הקבצים, לוחצים בשורת הכתובת, כותבים `powershell` ולוחצים Enter. אפשר גם להשתמש ב-Git Bash: קליק ימני בתוך התיקייה ← **Open Git Bash here**.
- **Mac / Linux:** פותחים Terminal ועוברים לתיקייה עם `cd`, למשל:
```
cd ~/Documents/my-project
```

## שלב 3: הפיכת התיקייה למאגר Git

```
git init
```
הפקודה יוצרת בתיקייה תיקייה נסתרת בשם `.git`, ששומרת את כל ההיסטוריה. מריצים אותה פעם אחת בלבד לכל פרויקט.

## שלב 4: יצירת קובץ .gitignore

לפני ה-commit הראשון יוצרים בתיקייה קובץ בשם `.gitignore`, ובו רשימת קבצים ותיקיות שלא יעלו לגיטהב. דוגמה לפרויקט Python:
```
.env
venv/
__pycache__/
```
חשוב במיוחד להכניס לרשימה את `.env` ואת כל קובץ שיש בו סיסמה או מפתח API.

## שלב 5: סימון הקבצים ובדיקה

```
git add .
git status
```
`git add .` מסמן את כל הקבצים בתיקייה. `git status` מציג אותם. בודקים ברשימה שלא מופיעים קבצים רגישים (כמו `.env`) או תיקיות מיותרות (כמו `venv`). אם מופיעים, מוסיפים אותם ל-`.gitignore`, ומריצים:
```
git rm -r --cached .
git add .
```

## שלב 6: commit ראשון

```
git commit -m "first commit"
```
אם מופיעה השגיאה `Please tell me who you are`, צריך קודם להגדיר שם ואימייל:
```
git config --global user.name "השם שלך"
git config --global user.email "המייל שלך"
```
ואז להריץ שוב את `git commit`.

## שלב 7: חיבור למאגר בגיטהב והעלאה

```
git branch -M main
git remote add origin https://github.com/USER/my-project.git
git push -u origin main
```
- `git branch -M main`: קובע שהענף הראשי ייקרא `main`.
- `git remote add origin ...`: מחבר את המאגר במחשב למאגר בגיטהב. במקום הכתובת לדוגמה מדביקים את הכתובת שהועתקה בשלב 1.
- `git push -u origin main`: מעלה את הקבצים. `-u` שומר את החיבור, כך שבפעמים הבאות מספיק `git push`.

בפעם הראשונה ייפתח חלון התחברות לגיטהב. מאשרים בדפדפן. גיטהב לא מקבל סיסמה רגילה בשורת הפקודה. אם מתבקשת סיסמה, משתמשים בטוקן גישה (Personal Access Token).

## שלב 8: בדיקה

מרעננים את עמוד המאגר בגיטהב. הקבצים צריכים להופיע, וקובץ `README.md` (אם יש) מוצג מתחת לרשימת הקבצים. מוודאים שקבצים רגישים כמו `.env` **לא** מופיעים.

## סיכום הפקודות להעלאה ראשונה

```
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/USER/REPO.git
git push -u origin main
```
את `USER/REPO` מחליפים בשם המשתמש ובשם המאגר שלך.

## העלאת עדכונים אחרי שהפרויקט כבר בגיטהב

כל פעם שמשנים קבצים ורוצים להעלות את השינויים:
```
git add .
git commit -m "תיאור קצר של השינוי"
git push
```
אין צורך לחזור על `git init` ועל `git remote add`. הם מתבצעים רק בפעם הראשונה.

## אם כבר יצרת את המאגר בגיטהב עם README

אם במאגר בגיטהב כבר יש קבצים (למשל README שנוצר באתר), ה-push הראשון ייכשל עם ההודעה `rejected` או `fetch first`. הפתרון: למשוך קודם את מה שיש בגיטהב ולשלב:
```
git pull origin main --allow-unrelated-histories
git push -u origin main
```
אם נפתח עורך טקסט עם הודעת מיזוג, שומרים וסוגרים אותו. אם מופיע קונפליקט, פותרים אותו ומבצעים commit.

## דרך חלופית: התחלה משכפול המאגר

אפשר גם ליצור את המאגר בגיטהב קודם (גם עם README), לשכפל אותו למחשב, להעתיק לתוכו את קבצי הפרויקט, ולהעלות:
```
git clone https://github.com/USER/REPO.git
cd REPO
(מעתיקים את קבצי הפרויקט לתיקייה)
git add .
git commit -m "add project files"
git push
```
בדרך הזו אין צורך ב-`git init` וב-`git remote add`, כי `git clone` כבר עושה אותם.

## העלאה דרך אתר גיטהב, בלי Git

1. בדף המאגר לוחצים **Add file** ← **Upload files** (במאגר ריק: הקישור **uploading an existing file**).
2. גוררים את הקבצים או התיקיות לחלון, או לוחצים **choose your files**.
3. למטה כותבים הודעת commit קצרה ולוחצים **Commit changes**.

מגבלות: עד 100 קבצים בכל העלאה, ועד 25MB לקובץ. הדרך הזו לא מעדכנת את הקבצים שבמחשב, ולכן לעבודה שוטפת עדיף להשתמש ב-Git.

## מגבלת גודל קבצים

גיטהב חוסם push של קובץ שגדול מ-100MB, ומזהיר על קבצים מעל 50MB. קבצים גדולים (סרטונים, מסדי נתונים, מודלים) לא מעלים למאגר. מוסיפים אותם ל-`.gitignore`.
