# בוט ידע ארגוני (RAG)

בוט שעוזר להשתמש ב-Git וב-GitHub, ועונה **רק** מתוך קבצי הידע שבתיקייה `data/`.
אם התשובה לא נמצאת במסמכים – הבוט אומר זאת ולא ממציא.

## הרצה

```bash
pip install -r requirements.txt
cp .env.example .env          # ולהכניס GOOGLE_API_KEY חינמי מ-Google AI Studio
# להכניס את המסמכים לתיקייה data/  (‎.md מומלץ, נתמכים גם ‎.txt ‎.pdf ‎.docx)
python ingest.py              # חלוקה, וקטורים ושמירה ב-ChromaDB
chainlit run app.py           # פתיחת הצ'אט בדפדפן
```

לתצוגה מימין לשמאל: אחרי ההרצה הראשונה נוצר הקובץ `.chainlit/config.toml`.
בסעיף `[UI]` יש להגדיר: `custom_css = "/public/rtl.css"`.

## מבנה הפרויקט

| קובץ | תפקיד |
|---|---|
| `config.py` | כל נקודות ההחלטה במקום אחד |
| `ingest.py` | טעינה, חלוקה לפי כותרות, יצירת וקטורים ושמירה ב-ChromaDB |
| `hebrew_bm25.py` | חיפוש מילות מפתח (BM25) מותאם לעברית |
| `rag.py` | הרחבת שאלה, חיפוש היברידי ויצירת תשובה |
| `models.py` | מודלי Gemini וניסיון חוזר בחריגה ממגבלת הקצב |
| `app.py` | ממשק הצ'אט ב-Chainlit |

## תהליך שאלה

```
שאלה ─► קצרה מ-5 מילים? ─כן─► Gemini מרחיב את השאלה
                │לא                     │
                ▼                       ▼
        ┌──── חיפוש היברידי ב-ChromaDB ────┐
        │  וקטורי (cosine)  +  BM25 עברי   │
        └──── מיזוג RRF ─► Top 4 קטעים ────┘
                        ▼
        Gemini עונה רק מהקטעים + מציג מקורות
```

## נקודות ההחלטה

| # | החלטה | הבחירה | נימוק |
|---|---|---|---|
| 1 | Vector DB | **ChromaDB** | נלמד בכיתה, רץ מקומית בלי שרת, משתלב עם LlamaIndex |
| 2 | ספרייה | **LlamaIndex** | לפי דרישת התרגיל: טעינת מסמכים, חלוקה, אינדוקס |
| 3 | חלוקת הידע | **לפי כותרות (Markdown)** | כל סעיף במסמך הוא יחידת משמעות שלמה, בלי העלות של חלוקה סמנטית |
| 4 | חפיפה | **ללא חפיפה** | סעיף לפי כותרת כבר שלם, וחפיפה הייתה מכפילה וקטורים |
| 5 | ספק API | **Gemini** | יש שכבה חינמית גם למודל התשובה וגם ל-embeddings |
| 6 | Top K | **4** | מספיק כדי לכסות שאלה שהתשובה עליה פזורה בשני סעיפים, בלי להעמיס הקשר |
| 7 | מודלים | **gemini-3.8-flash** (תשובה), **gemini-embedding-001** (וקטורים) | שניהם בשכבה החינמית ותומכים בעברית |
| 8 | הרחבת שאלה | **רק לשאלה של פחות מ-5 מילים** | שאלה כמו "חניה?" לא מוצאת כלום; שאלה מפורטת לא צריכה קריאת API נוספת |
| 9 | צורת חיפוש | **היברידי: וקטורי (cosine) + BM25, מיזוג RRF** | הווקטורים מבינים משמעות, ו-BM25 מוצא מספרים, שמות ומונחים מדויקים |
| – | קליינט | **Chainlit** | ממשק צ'אט מוכן, כולל הצגת מקורות בצד |

## 3 בעיות שנתקלתי בהן במהלך הפיתוח והפתרונות

### בעיה 1: חיפוש BM25 לא מצא מילים בעברית
**הבעיה:** BM25 מחפש התאמה מדויקת של מילים. בעברית אותיות השימוש מוצמדות למילה,
ולכן שאלה עם המילה "תשלום" לא מצאה סעיף שבו כתוב "לתשלום" או "והתשלום".
הטוקנייזר המובנה בספריות BM25 בנוי לאנגלית (stemmer ומילות עצירה באנגלית).

**הפתרון:** כתבתי טוקנייזר עברי (`hebrew_bm25.py`): מסיר ניקוד וגרשיים, ולכל מילה שומר
גם את הצורה המקורית וגם את הצורות בלי התחיליות ו/ה/ב/כ/ל/מ/ש. מכיוון שלא תמיד ברור כמה
אותיות הן תחילית ("בהוראת" = ב+הוראת), נשמרות כל האפשרויות. כך "תשלום" מתאים ל"לתשלום".

### בעיה 2: חלוקה לפי כותרות יצרה קטעים קטנים מדי וגדולים מדי
**הבעיה:** חלוקה לפי כותרות תלויה במבנה המסמך. כותרת ראשית בלי טקסט הפכה לקטע של
מילה אחת – וקטור חסר משמעות שתפס מקום ב-Top K. מצד שני, סעיף ארוך בלי כותרות משנה
יצר קטע ענק שהווקטור שלו "מטושטש". בלי חפיפה, פיצול שרירותי שלו היה מאבד את ההקשר.

**הפתרון:** ב-`ingest.py`:
- סעיף שיש בו רק כותרת, בלי תוכן, מאוחד עם הסעיף שאחריו. בהתחלה איחדתי כל סעיף קצר מ-120 תווים,
  אבל אז במילון המונחים 15 מתוך 29 ההגדרות אוחדו עם מונח אחר. לכן הכלל בודק רק את אורך התוכן בלי הכותרת.
- בלוק ה-front matter שבראש כל קובץ (`--- title/topic ---`) מוסר מהטקסט ועובר למטא-דאטה, כדי שלא יידבק לסעיף הראשון.
- סעיף ארוך מ-800 טוקנים מפוצל שוב לפי משפטים (עדיין ללא חפיפה), וכל חלק מקבל
  בראשו את שרשרת הכותרות שלו, כך שההקשר נשמר גם בלי חפיפה.
- קבצים בלי כותרות (PDF, Word) מחולקים לפי משפטים כגיבוי.

### בעיה 3: שגיאת 429 (חריגה ממגבלת הקצב) בשכבה החינמית
**הבעיה:** בשכבה החינמית של Gemini יש מגבלה על מספר הבקשות לדקה. בזמן יצירת
הווקטורים לכל המסמכים התהליך נפל באמצע עם `429 RESOURCE_EXHAUSTED`, וגם בצ'אט –
שאלה קצרה צורכת שתי קריאות (הרחבה + תשובה) ולפעמים נכשלה.

**הפתרון:** ב-`models.py` הוספתי פונקציה `with_retry` שמזהה שגיאת מגבלת קצב ומנסה
שוב עם המתנה הולכת וגדלה (5, 10, 20 שניות...). ב-`ingest.py` הקטעים נשלחים במנות של 20,
ובכל הרצה האוסף ב-ChromaDB נבנה מחדש כדי שהרצה חוזרת אחרי כישלון לא תיצור כפילויות.
